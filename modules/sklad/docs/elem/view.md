# Карточка элемента

Маршрут: `/sklad/elem/view?id=<Код>`. Живёт в модуле «Склад», а не в «Закупках»: карточку открывают
все отделы, и закупки ссылаются на неё, а не наоборот.

Открывается двойным щелчком по строке списка: «Статистика» (в Access `frmMinimum.OpenKartElem`),
счёт на элементы и другие экраны — так же, как `DoCmd.OpenForm "Fobnovlen1", acNormal, , , acFormEdit, acDialog, Код`.
Окно открывается отдельно, список остаётся на месте.

Для кого: все отделы — карточка одна, видимость и доступность отдельных полей и кнопок
включается правами (в Access через `GetPermission`, здесь через `Yii::$app->user->can(...)`).

## Что показывает
- Код элемента, «РГМ» (если код пришёл отрицательным — в Access `Me!Rgm = 1`).
- Основные поля: наименование, серия, номинал, корпус, изготовитель, количество, цены, место хранения, примечание.
- Все остальные поля записи — в сворачиваемом блоке «Все поля записи».
- Источник — `exec dbo.xp_Fobnovlen1Shelf <Код>` (как `Form_Open` в Access).

## Списки (вкладки)
Читаются при первом щелчке по вкладке, а не все сразу: у больших элементов история бывает в тысячи строк.

| Вкладка | Процедура | Что в ней |
|---|---|---|
| История | `xp_HistoryElem ID, 2, Abs(FakeSch), 0, ''` | приход и оплаты: счёт, накладная, количество, цены, сроки, гарантия |
| Договоры | `xp_FObnovlen1GetDogs '<ГдеКупил>'` | № и дата договора, срок гарантии, организация, описание |
| Наименования | `xp_FObnovlenGetNaim ID, 1` | серия, наименование, номинал, производитель |
| Отслеживание | `xp_SkladTackingAnalogs ID` | связанные элементы (аналоги) |
| Коды | `xp_SkladCodesRS ID, 0` | коды идентификации (`RS4SkladCodes`) |

Колонки, подписи, ширины и порядок взяты из подформ Access (`subfrmObnovlen1`, `subfrmFObnovlen1_01`,
`subfrmSkladNaim`, `subfrmDef`). Скрытые в Access колонки (`ColumnHidden`) не выводятся: `UpKoef`, `PredShcID`, `AllID`,
`IDSchEl`, `ImportDate`, `AdditFile` и др. У «Истории» включены дата выпуска, срок гарантии и гарантия до —
в Access их показывает `Form_Open`. У «Кодов» в `Form_Open` оставлены только два столбца: `Def` — «Код»
(тип кода) и `Nme` — «Значение», шириной по 1400 твипов. Поля, которых в дизайне не было,
дописываются в конец. Для «Отслеживания» дизайна подформы нет — колонки строятся по фактическим полям.

## Права
Отдельного права у карточки нет — так же, как в Access. Пускаем любого вошедшего, потому что
право проверяет тот экран, откуда карточку открыли (`form:frmSt`, `form:frmStat` и т.д.).
Редактирование полей в дальнейшем будет закрыто своими правами:
`EditEl`, `TaskNaborNakl`, `Mnl-Kat`, `ChgOptPrice`, `ChgIzgElF`, `ChgKrpElF`, `UpdMinSklad`,
`TSManual`, `AllowDocSk`, `DisAllowNewKat`, `OvrrideCustStatus`.

## Пока не сделано
- Раскладка 1:1 с Access (около 230 элементов) — поля пока списком.
- Редактирование и сохранение полей, проверка `fnAllowChgElem` для связанных элементов ПГ.
- Кнопки-действия (более 50): печать этикетки, перемещение, просушивание, изоляция, фото, заказы и т.д.
- Журнал открытия формы (`OpenFormLog`, `Put2LogOpenForm`) — в Access пишется при каждом открытии карточки из «Статистики».
- Двойной щелчок по «Код» в «Статистике» при праве `ProblEl` и виде «Проблемы» открывает не карточку, а `frmfndStatus 25`;
  двойной щелчок по «ГдеКупил» со значением «ПЕРЕЛОЖИТЬ НА СКЛАД» — `frmMoveEl`.
- В «Истории» фильтры формы (`fndUpak`, «Задержка поставки», «Дата импорта», даты интервала) пока не вынесены:
  список всегда читается с параметрами по умолчанию, как при открытии карточки.
- Подпись над «Отслеживанием» в Access меняется на «Аналоги», когда связанных элементов нет (`SetRS4TrackingAnalogs`).
