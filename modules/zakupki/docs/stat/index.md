# Статистика

Для кого: снабжение.
Что делает: список элементов (потребность, наличие, цены, проблемные позиции) по выбранному виду. Каждый вид — своя процедура `dbo.xp_frmStNewRS…`, поэтому состав и порядок колонок меняются вместе с видом.

## Фильтры
- **Вид** — список из `exec dbo.xp_GetVidSel`. Смена вида сразу перечитывает список и перестраивает набор фильтров (как `fnRepaintFormStat` в Access).
- **Поиск** — по части текста, как `FindElem` в Access (`%текст%`). Пусто — весь список.
- **Фирмы** (`f`) — мультивыбор, как кнопка «Выбрать фирму» (`frmFndFirm`, OpenArgs 7). «Все» — `%`, иначе ID через запятую. Это второй параметр процедуры вида. В виде 7 скрыт вместе с `TypeSel`.
- **Фирма (WhatFirm)** — одиночный список `exec dbo.xp_GetWhatFirm`. В виде 7 скрыт вместе с `TypeSel`.
- **Менеджер** — `SkladManagers`, `exec dbo.xp_GetSkladManagersNew`. От него зависят ответственный (`Otv`, 3-я колонка) и раскраска долгов (4-я колонка). В виде `b` список берётся из `exec dbo.xp_SkladTrackingSprLst 1`, значение — первая колонка (текст), `Column(2)` — ID. В виде 7 скрыт вместе с `TypeSel`.
- **Дата документа** — `PickDate` / `PickDate2`: если заданы обе даты, список строится процедурой `xp_frmStNewRS1_1` (в Access так же: заполненный `PickDate` перекрывает вид). Поля видны только в виде 1 при `fltZ1 = 1`; при скрытии Access очищает значения.
  - В Access оба поля `Locked = True` — вручную в них не вводят. Даты выбираются кнопкой **«Даты»** (`GetInt_Click` → `frmGetInterval`), которая заполняет `PickDate`/`PickDate2` и сразу перечитывает список (`cboflt_AfterUpdate`).
  - В вебе поля тоже `readonly`, а кнопка «Даты» открывает то же окно интервала (`web/js/interval.js`, как на других экранах) и после выбора отправляет форму.
- **Сырьё** — `TypeSel`: НЕ давальческое / давальческое / не важно. В виде 7 скрыт.
- **Заказ** — `fltZ1`: «Заказ>0» (суффикс `_0` у имени процедуры) / «Все». В виде `b` подписи другие: «Все» / «Нет счетов более недели».
- **Состояние** — `fltStatProblEl`, `exec dbo.xp_StatWorkWithProblemLstSost 1`. Виден в видах 1 и 3; значение 255 — все состояния.
- **ФЗ-275** — список `exec dbo.xp_frmStLstFZ275`: `0` — «(Все записи)», `-2` — «ПГ», `-3` — «не ПГ». Виден только в виде 1, в остальных видах принудительно 0.
- **Применить** — перечитать список с текущими фильтрами.

### Видимость фильтров по видам
Правила взяты из `fnRepaintFormStat` (и `fltZ1_AfterUpdate`); в вебе их применяет `StatFilter::applyViewRules()` и методы `show*()`.

| Вид | `fltZ1` | `fltZ1` виден | ФЗ-275 | Состояние | Даты | Фирмы | WhatFirm / Менеджер | Сырьё | `SkladID` |
|---|---|---|---|---|---|---|---|---|---|
| 1 | 1 | да | да | да | да (при `fltZ1=1`) | да | да | да | 0 |
| 2 | 1 | да | нет | нет | нет | да | да | да | 0 |
| 3 | 0 | нет | нет | да | нет | да | да | да | 0 |
| 4 | 1 | да | нет | нет | нет | да | да | да | 0 |
| 5 | 0 | нет | нет | нет | нет | да | да | да | 0 |
| 7 | 1 | нет | нет | нет | нет | нет | нет | нет | 0 |
| 9 | 1 | нет | нет | нет | нет | да | да | да | 0 |
| a | 1 | нет | нет | нет | нет | да | да | да | 0 |
| b | 1 | да | нет | нет | нет | да | да | да | -500 |

Даты (`PickDate`/`PickDate2`) видны только в виде 1: `PickDate.Visible = fltZ1 = 1 And lgOp = "1"`.

Для вида `b` подписи `fltZ1` — «Все» / «Нет счетов более недели», заголовок группы не выводится.
`FndZac` в ветке `b` скрывается, но общий блок после `Select Case` снова её включает (`FndZac.Visible = TypeSel.Visible`, а `TypeSel` скрыт только в виде 7) — поэтому в вебе она видна.

Правила по виду применяются **только при смене вида** — как `fnRepaintFormStat`, которую Access вызывает из `ПолеСоСписком24_AfterUpdate`. Для этого форма передаёт скрытое поле `vidPrev` (вид на момент отправки): если `vidPrev` совпадает с `vid`, выбор пользователя не перебивается (например, «Все» в видах 2, 4 и `b`). Скрытые фильтры (`FZ275`, даты, `SkladID`) приводятся к значениям Access всегда.

### Первое открытие
`cboflt_AfterUpdate` при `FirstTime = True` и фильтрах по умолчанию (`f = "%"`, `SkladManagers = "%"`, `TypeSel = 1`, `WhatFirm = 0`) вызывает процедуру с `SkladID = -500` — это служебный режим «список пуст, установите фильтры». Поэтому форма открывается без строк и с подсказкой «Выберите фильтры». Как только меняется любой фильтр (или нажато «Применить»), `FirstTime` уже `False` и грузится обычный список.

`filt1` / `filt2` / `filt3` (поставщик, город, дата) в Access — фильтры временной таблицы счетов (`#tblTmpSt`, кнопки `filt9` / `filt10`), а не параметры процедуры вида. Переносятся отдельно, вместе с экраном фильтра по счетам.

Поля процедуры, которых в подформе нет (`Элемент`, `Заказано`, `ЦенаОптовая`, `FirstName`, `ProblKol`, `UchetID`, `SharpName`, `CreatorCode`, `ExistMove`, `UPKoef`, `MinToBuy`, `TS`, `FullDolg`, `KolInRes`, `SrcProblEl`, `KolZak`, `Свободно`, `DtaPost`, `IsExactDate`, `MinStartZak`, `AppearMinTxt`, `AppearMinByAdd`, `NedopolByNakl`, `Avt`, `IsDelayed`, `NU`, `flgNU`), скрыты — список в `StatColumns::HIDDEN`. Незнакомые поля набора выводятся в конце как есть, чтобы новые версии процедур не теряли данные.

- Щелчок по заголовку сортирует (повторный — в обратную сторону), ✕ в шапке списка возвращает исходный порядок процедуры.
- Щелчок по строке делает её текущей (подсветка, как `OnCurrent` в Access).
- Двойной щелчок по строке открывает карточку элемента (`/sklad/elem/view?id=…`, форма Access `Fobnovlen1`)
  в отдельном окне — как `OpenKartElem` в Access. Список остаётся на месте.

## Двойной щелчок по колонке
Разные колонки списка ведут себя по-разному — так же, как обработчики `*_DblClick` подформы `frmMinimum`.

| Колонка | Что происходит |
|---|---|
| Наименование, Номинал, Корпус, Изготовитель, Долг, Количество, Недополучено, `txtSV` | карточка элемента (`Fobnovlen1`) |
| Код | выбор состояния проблемы, если есть право `ProblEl`, вид 1 или 3 и в «ГдеКупил» есть слово «Проблемы»; иначе карточка элемента |
| ГдеКупил | при значении «ПЕРЕЛОЖИТЬ НА СКЛАДЕ» — форма переноса `frmMoveEl` (пока не перенесена, показывается сообщение); иначе карточка |
| Аналог | просмотр текста «Аналог элемента» (в Access `frmShowPrim`, ветка 58) |
| Примечание | правка примечания элемента, до 500 символов (`xp_SkladUpdPrim`); ответ 2 — «нет прав» |
| `SostProblEl` | только вид `b`: комментарий производства, до 1024 символов (`xp_SkladTrackingUpdComm`) |
| `DfltIsp` | только вид `b`: просмотр «Информация» |
| Служебные (`LowR`, `NotRec`, `VP5`, `NoAnalog`, `KolPok`, `FZ275Kol`, `RequestSch`, `IDInvoice`, `OrderKat`, `chk`, `MainPlace`, `IDCursor`) | ничего — в Access у них обработчик не задан |

После сохранения примечания, комментария или состояния список перечитывается и возвращается к той же записи по «Код» — как `Form_Timer` / `StndOnLne` в Access.

## Резервы
- Под списком — панель резервов текущего элемента (подформа Access `SubMinimFilter`).
- Источник: `exec dbo.xp_SubMinimumFilter @txtID, @Rgm`, где `@txtID` — «Код» выбранной строки,
  `@Rgm` — вид списка строкой. Для видов `1`, `5`, `8` процедура считает, из-за каких резервов
  элемент попал в долг, и помечает их `IsGuilty = '!'`; для остальных отдаёт строки без отметок.
- Порядок строк задаёт сама процедура: `IDRes = 8579` первым, затем виновные, затем по
  `DtaPost`/`Дате` убыв. — как `ORDER BY` в Access.
- Колонки и подписи — `StatColumns::RESERVE_META` / `RESERVE_ORDER`. Порядок взят из
  `ColumnOrder` формы после `Form_Load` (там `CalcPrc.ColumnOrder = 4` сдвигает остальные):
  Пробл, В, Дата, Расч.ст-ть,$, Жел.дата пост.р-ва, План.старт, Таргет,USD,
  Максим. цена закуп.,USD, Осталось (`Razn` — «5н.3д.»), Название темы, Примечание,
  Заказчик, Исп-ль, ИНН, Область применения, Уровень токсичности, Ответственный,
  Отв.техподдержки, Изделий, Кол-во (`Резерв`), Всего (`AllKol`), Срок не согл.,
  ФЗ275., Заказ (`NumZakas`).
- При виде `b` `fnRepaintFormStat` (`f = lgOp = "b"`) скрывает закупочные колонки:
  Название темы, Жел.дата пост.р-ва, Таргет, Максим. цена, Изделий, Кол-во, Всего,
  План.старт, В, Расч.ст-ть, ИНН, Уровень токсичности, Область применения, Исп-ль,
  Срок не согл., ФЗ275. — `StatColumns::RESERVE_HIDDEN_IN`.
- Колонка «В» в форме вычисляемая: `=IIf([IsExactDate]=True,"!","")` — считается в
  `StatService::reserves()`. Служебные `IDRes`, `IDProcess`, `IsExactDate`, `Colr` скрыты.
- Данные грузятся при выборе строки списка (`StatController::actionReserves`), как перезапрос
  подформы на `Form_Current`.

## Аналоги
- Под списком — панель аналогов текущего элемента (подформа Access `subFrmStAnalog`).
- Аналоги грузятся при выборе строки: `exec dbo.xp_frmStRS1Analog @Код`. Процедура подбирает позиции по Элемент/Серия/Наименование/Номинал исходного элемента и сортирует по количеству.
- Колонки — как в подформе: Наименование, Номинал, Корпус, Примечание долга, Кол-во, Долг, Недополучено, Мин. долг, Заказать, Код, Серия, Кат.
- «Заказать» в Access — вычисляемое поле (`IIf([Недополучено]-[Долг]<0, [Долг]-[Недополучено], 0)`), считается при выводе.

## Футер списка
Под таблицей — поля подформы `frmMinimum`, как в Access:

| Поле | Что это | Когда видно |
|---|---|---|
| Граница (`PriceBound`) | цена, от которой позиция выделяется в списке. По умолчанию `GetAdr(60)`: для вида 7 — в долларах, для остальных — в рублях (умножается на курс) | все виды, кроме `b` |
| Курс (`KursUSD`) | курс доллара с экрана учёта (`xp_GetKursByVal 840`), только для чтения | все виды, кроме `b` |
| Разница (`Razn`) | разница цены, передаётся процедуре вида 7 | только вид 7 |
| «Выборка без учёта тех.запаса» (`WarnTS`) | предупреждение: тех.запас учитывает только вид 1 | все виды, кроме `1` |

- В Access граница задавалась двойным щелчком (`InputBox` «Введите новое значение границы»), здесь — обычное поле;
  Enter или «Применить» перечитывает список с новыми `Bnd` / `Razn` / `Kurs` (`Razn_AfterUpdate`).
- При смене вида граница пересчитывается по курсу: вход в вид 7 — деление на курс, выход — умножение
  (`ПолеСоСписком24_AfterUpdate`, флажок `dl`).
- Позиции, у которых `LowR` (сумма, $) больше или равна границе, выделяются синим жирным
  (`fnRepaintFormStat`: `LowR >= PriceBound`).
- В виде 7 фильтр «Сырьё» (`TypeSel`) скрыт — как в Access.

## Подсказки по колонкам
В Access подсказку показывало поле `Descr` главной формы: обработчики `*_GotFocus` подформы `frmMinimum` подставляли туда текст, `*_LostFocus` — очищали. В вебе подсказка появляется под списком при наведении на ячейку (`StatService::hints`).

| Колонка | Подсказка | Когда |
|---|---|---|
| Код | синий — элемент можно забирать | все виды, кроме `b` |
| ГдеКупил | голубой — задание на перенос для склада, кирпичный — для входного контроля | все, кроме `b` |
| Количество | жёлтый — есть проблемные элементы | все, кроме `b` |
| Наименование, Примечание | жирный — жёсткий срок поставки, зелёный — срок меньше текущей даты | все, кроме `b` |
| Номинал | розовый — не рекомендуемый к поставке, коричневый — на согласовании | все, кроме `b` |
| Изготовитель | зелёный — в работе, жёлтый — тех.запас, синий — контроль сроков | только вид `1` |
| Недополучено | зелёный — доставка на сокол | только вид `1` |
| Корпус | розовый — в резерв не заказан более недели, коричневый — на согласовании | когда включена раскраска долгов |
| Долг | голубой — заказывается на Торэкс | когда включена раскраска долгов |

Раскраска долгов — `FlgPaintDolg` (`xp_GetSkladManagersNew`, третья колонка), тот же признак, что добавляет `&` к строке поиска.

## Автообновление
- Список перечитывается сам каждые 9 минут (`TimerInterval = 540000`, как `Form_Timer` в `frmMinimum`).
- Обновляется только тело таблицы: фильтры и недописанный текст в полях не сбрасываются.
- После обновления экран возвращается к текущей записи по «Код» (`txtID` → поиск записи заново), прокрутка сохраняется.
- Скрытая вкладка запросов не шлёт; при возврате на вкладку список обновляется сразу, если 9 минут уже прошли.
- Кнопка «⟳ Обновить» перечитывает список немедленно.

## Отличия от Access
- Раскладка одна — современная; вид «как в Access» для этой формы не делается.
- Строка поиска не перехватывает клавиатуру: чтобы начать поиск, поставьте курсор в поле «Поиск».
- Цвета подсказок (проблемные, не рекомендованные, отрицательное количество, запрос счёта) сохранены.
- Кнопки печати, Excel, заказов, перемещения, трекинга и прочие действия формы `frmSt` — вторая очередь.

## Пока заглушки
- Ответственный (`Otv`, в Access `SkladManagers.Column(2)`) и признак подсветки долгов (`NeedPaintDolg`, `Column(3)`) читаются из выбранного менеджера в классе `StatContext`; для «%» — 0 / false, как в Access. Для вида `b` список менеджеров — `xp_SkladTrackingSprLst 1` (значение — `fld1`, `Column(2)` — `ID`). Если процедуры нет или она ничего не вернула — 0 / false.
- Курс USD (нужен только виду 7) — `xp_GetKursByVal 840`; если в фильтре курс задан, берётся он.
- Виды `9` и `a` вызываются штатно (`xp_frmStNewRS9_0`, `xp_frmStNewRSa_0`). Их результат строится по `dbo.Sklad1C` с `Who = CURRENT_USER`; таблицу наполняет `PrepareMinKolFrom1C` вне формы `frmSt` — при незаполненной таблице список будет пустым (как и в Access).
- Форма переноса элемента `frmMoveEl` (двойной щелчок по «ГдеКупил» = «ПЕРЕЛОЖИТЬ НА СКЛАДЕ») не перенесена: показывается сообщение.
- Панель `SubMinimumFilter` — не перенесена.
- Фильтр по счетам (`filt1`/`filt2`/`filt3`, временная таблица `#tblTmpSt`) — вторая очередь.
- Групповое примечание (`btnChgPrimGroup`) и кнопка «Счёт зап.» (`RequestSch`) — вторая очередь.
